# Forge agent-service staging host (Fly.io)

Staging only. `FORGE_DEPLOY_ENV=production` refuses to boot until a production launch is
approved. Deploying is a PAID step (see `docs/verification/step0.md` for cost and cap).

## Shape
- One Fly app `saasytoad-forge-agent-staging`, region `iad`, ONE `shared-cpu-1x` 512 MB
  machine, ONE 1 GB volume `forge_staging_data` at `/data`, shared IPv4 + IPv6 only (no
  dedicated IPv4). `auto_stop_machines = "stop"`, `min_machines_running = 0`.
- Image: `apps/agent-service/Dockerfile` (repo-root context). Runs as the unprivileged `node`
  user; the entrypoint only chowns the volume, then drops root and all capabilities.
- Health: `GET /health` (liveness: status, `version` = FORGE_BUILD_SHA, deployEnv, region).
  `GET /ready` (Fly check): 200 only when the model client is the GenX Router client and the
  sandbox provider is real (not the mock). Neither endpoint calls a paid API or returns a secret.
- Single instance by design: workspaces are in memory and the sandbox spend ledger lives on
  the volume. Scaling past one machine needs the shared Postgres ledger first.

## Boot-time refusals (`assertStagingEnv`)
Staging will not start (names listed, never values) unless: `NODE_ENV=production`; a unique
32+ char `AGENT_SERVICE_SECRET`; `ALLOWED_ORIGINS` = exact https origins (no wildcard);
`GENX_ROUTER_URL` (https) + `GENX_ROUTER_FORGE_TOKEN`; `SANDBOX_PROVIDER=e2b` +
`E2B_API_KEY`. It also refuses `OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`
(every model call goes through GenX Router OS) and Stripe keys (billing is tested separately).

## Secret handling
- One file per variable, named exactly like it, in `/workspace/forge-game-proof/.secrets/staging`
  (dir 700, files 600, outside every repo). Scripts refuse other modes, multi-line values
  (an embedded newline could smuggle a second variable), files owned by someone else, and the
  forbidden names (direct model keys, Stripe, `ROUTER_OS_OPERATOR_TOKEN`, `TOGETHER_API_KEY`).
- `scripts/staging/import-fly-secrets.sh` pipes `NAME=VALUE` lines to `fly secrets import --stage`
  over stdin: never argv, never echoed. It prints names with 12-hex fingerprints only.
- Nothing secret goes into chat, logs, the repo, or `fly.toml`.

## Token rotation (hosted Forge never uses the local token)
1. `new-secret.sh .secrets/staging/GENX_ROUTER_FORGE_TOKEN` writes a NEW 384-bit token (done
   2026-11-10, fingerprint `99f5b2b0a638`). The local step-1 token
   (`.secrets/forge-app-token`) stays local; `import-fly-secrets.sh` refuses it by hash.
2. Set the same value as `ROUTER_OS_FORGE_APP_TOKEN` on the Router Preview environment, scoped
   to the Forge branch only, read from the file (never pasted). The Router already refuses a
   token equal to `ROUTER_OS_OPERATOR_TOKEN`, so the operator token can never be the app token.
3. Stage it on Fly with `import-fly-secrets.sh`, then deploy.
4. To rotate again: move the file aside, generate a new one, update the Router preview first,
   then Fly. In between, Forge gets a clean 401 (fails closed). To revoke: delete the Router
   preview variable; every Forge call then fails closed.
